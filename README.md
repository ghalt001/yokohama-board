# 横浜 イベント・入港ボード

横浜の主要施設のイベント(開場・開演・終演)と、客船の入港予定を毎朝自動で集めて、
スマホ/PCで見られる1枚のページにまとめるツールです。サーバー代はかかりません
(GitHub の無料枠で動きます)。

- 毎朝 日本時間 4:00 頃に自動更新(5:30 頃にもう一度)
- 今日の分が上、明日の分は折りたたみ
- 「終演の目安(早い順)」で、人が動き出す時間帯が一目で分かる
- 取得に失敗した施設は「なし」ではなく **⚠取得失敗** と表示(見落とし防止)
- **パスコード保護**: ページを開くとパスコード入力画面が出ます。公開されるデータは暗号化されており、
  パスコードを知らない人には中身が読めません(「この端末で記憶する」で2回目以降は入力不要)

## 自動取得の対象

| 状態 | 対象 |
|---|---|
| 自動取得 | 客船入港(大さん橋・新港・大黒)、Zepp Yokohama、横浜武道館、Kアリーナ横浜、横浜BUNTAI、日産スタジアム、ぴあアリーナMM、横浜赤レンガ倉庫、横浜アリーナ(一部) |
| 未対応(公式サイトへのリンクのみ) | 横浜スタジアム、パシフィコ横浜 |

横浜アリーナは月間一覧が読み取れないことがあり、その場合は「要確認」と表示されます。

## はじめての GitHub 設定手順(約20分)

### 1. アカウントを作る
1. https://github.com を開き **Sign up** からメールアドレスで登録(メール認証あり)。
2. ユーザー名はそのまま URL の一部になります(例: `https://ユーザー名.github.io/…`)。

### 2. 置き場(リポジトリ)を作る
1. 右上の **+** → **New repository**。
2. **Repository name** は分かりやすい名前で構いません(例: `yokohama-board`)。このまま URL の一部になります。
   ※パスコードで保護するので、推測されにくい名前にする必要はありません。
3. **Public** を選びます(無料で公開ページを使うために必要です)。
   リポジトリの中身(プログラム)は誰でも見えますが、イベント情報は暗号化されて別に公開されるため、パスコードなしでは読めません。
4. 他のチェックは入れず **Create repository**。

### 3. ファイルをアップロードする
1. ダウンロードした zip を解凍します。
2. リポジトリの画面で **uploading an existing file** のリンクを押します。
3. 解凍してできたフォルダの **中身すべて**(`board` `tests` `.github` `requirements.txt` `.gitignore` `README.md`)をドラッグ&ドロップします。
4. 下の **Commit changes** を押します。

> `.github` フォルダが一覧に出ていない場合: **Add file → Create new file** を押し、
> 名前欄に `.github/workflows/daily.yml` と入力(`/` を打つとフォルダになります)、
> 付属の `daily.yml` の中身を貼り付けて **Commit changes**。

### 4. 公開設定を1つだけ変える
**Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。

### 5. パスコードを登録する(必須)
1. パスコードを決めます。**10文字以上**(短いと作成が失敗します)。
   英数字を混ぜた10〜12文字か、無関係な単語を3〜4個つないだもの(例: `ramen-kaigan-tsuki-47`)がおすすめです。
   誕生日や電話番号など推測できるものは避けてください。
2. **Settings → Secrets and variables → Actions → New repository secret** を押します。
3. **Name** に `BOARD_PASSCODE`(半角大文字、そのまま)、**Secret** に決めたパスコードを入れて **Add secret**。

パスコードを登録しないと、自動実行は「保護なしでは公開しません」と表示して止まります(意図した安全装置です)。
パスコードを変えたいときは、同じ画面で `BOARD_PASSCODE` を更新して、次の「手動で動かす」をもう一度行ってください。

### 6. 初回を手動で動かす
1. 上の **Actions** タブを開きます(「ワークフローを有効にしますか」と出たら有効にします)。
2. 左の **daily-board** → 右の **Run workflow** → **Run workflow**。
3. 2〜3分で緑のチェックになります。完了後、`deploy` の枠に表示される URL
   (`https://ユーザー名.github.io/リポジトリ名/`)が、見るページです。

### 7. 毎日の使い方
- PC: そのURLをブックマーク。初回にパスコードを入力(「この端末で記憶する」にチェックしたままにします)。
- iPhone: Safari で開く → パスコードを入力 → 共有ボタン → **ホーム画面に追加**。
- 以降は毎朝自動で更新されます。何も操作は要りません。
- 端末を人に貸すときなど、記憶を消したい場合は、ブラウザのサイトデータ削除で消せます。

### パスコード保護について(仕組みと限界)
- 公開されるのは暗号化されたデータ(AES-256)とパスコード入力画面だけで、復号はお使いのブラウザの中で行います。
- パスコードを知らない人には読めませんが、暗号化データそのものは誰でも入手できます。
  そのため、**短い・推測しやすいパスコードだと、時間をかけて試される**余地があります。長めのパスコードにしてください。
- 本格的なアクセス制御(ログイン、閲覧履歴の管理など)ではなく、「検索に出ない・たまたま見つけた人には読めない」ための軽い保護です。

## 困ったとき

- **赤い×になった / 表示がおかしい**: Actions の該当の実行を開き、画面下の **Artifacts** にある
  `raw-html`(取得した生のページ)と、エラーの画面を開発者に送ってください。
  サイト側のデザイン変更で読み取れなくなるのは、半年に1〜2回は起こり得ます。
- **「保護なしでは公開しません」で止まった**: 手順5の `BOARD_PASSCODE` が未登録、または10文字未満です。
- **パスコード画面で「開けません」と出る**: https のURL(`https://…github.io/…`)で開いているか確認してください。
- **更新が止まった**: GitHub は、リポジトリに60日間何も動きがないと定期実行を止めます。
  メールで通知が来るので、Actions タブの **Enable workflow** を押せば再開します。
- 取得は1日あたり数十リクエスト程度で、1秒以上の間隔を空け、各サイトの robots.txt に従います。
  個人利用の範囲でお使いください。

## 開発者向け

```bash
pip install -r requirements.txt
python tests/test_sources.py        # 解析処理のテスト(ネットワーク不要)
python tests/test_protect.py        # パスコード保護のテスト
python -m board.main --out site --raw raw   # 実サイトから取得して site/index.html を生成(保護なし・手元確認用)
BOARD_PASSCODE='十分長いパスコード' python -m board.main --out site --require-passcode   # 本番と同じ(暗号化)
```

- `board/sources.py` : サイトごとの取得・解析(1サイト=1関数)
- `board/render.py`  : 表示用HTMLの生成
- `board/main.py`    : 全体の流れ(1か所失敗しても他は続行)
